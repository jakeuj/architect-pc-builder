# 估價網站介面與驗收

建立新站或改版網頁時讀取本文件。資料結構與價格規則見 [site.md](site.md)；介面調整沿用既有 `CoolPC` 對照、計價與編解碼。

## 模板與客製

- `templates/index.html` 為介面及事件，`templates/builder.css` 為樣式，`templates/coolpc-live.js` 為報價核心 (2026-10-22 起 `encodeQuote`／`decodeQuote` 是 async：新連結 `2` 字首 deflate 壓縮，`1` 字首舊連結照收)，`templates/builder-ui.js` 為搜尋／用途分類／選件預覽與套用、改單差異 (`diffQuote`)、價格歷史 (`historyStats`／`sparkline`)、最近開過 (`recentUpsert`／`recentClean`) 與 QR Code 產生器 (`qrMatrix`／`qrSvg`) 的純 UI 邏輯。`build_site.py --init` 將四個資源放入 docs；一般資料生成寫 data.json、data-more.json 與 history.json (主機型錄的價格歷史，內容沒變時不重寫；`--backfill-history` 從 git 一次性回填，格式見 [site.md](site.md))。BuilderUI 可由瀏覽器載入或以 CommonJS 跑 Node 測試。
- 新站預設使用石墨黑背景、深灰面板、青藍重點色與數字對齊；既有站依使用者已選定的風格調整，不因同步模板而強制重設。
- `--init` 保留已存在的檔案；更新既有站時明確合併 HTML 與 CSS。`--force` 會連設定、Worker 與 workflow 一起覆寫，只用於已確認要完整重建的情境。
- 模板使用通用標題與相對資源路徑。設定 `site.json` 後，同步初始 HTML 的 title、h1、簡介、description 與 OG 標題／描述；正式 URL 確認後再加 canonical、`og:url`。模板不帶特定專案的網域或 GitHub 連結。

## 布局與操作

- 簡短介紹、報價日期／快照來源 → 用途選擇或收合的目前配置 → 零件清單與估價摘要 → 說明與頁尾。卡片明確標「預設總計」，收合摘要與估價摘要均是目前估價單，修改後不可誤用原菜單價格。
- 桌面 ≥1024px 採雙欄，右側摘要 sticky；較窄畫面為單欄與底部總價／分享列。用 ResizeObserver 測量固定列高度，內容與 toast 依該高度留空間，列本身含 safe-area；現價標示換行後也不能蓋住最後內容。
- 零件列完整品名自然換行，數量與價格同列，保留條件／歷史價提示；價格下另有一行 `.d.hist` 小字「30 天最低 $X／最高 $Y」加階梯迷你折線 (2026-10-22 起；`history.json` 背景載入後才出現，30 天內沒變只寫「30 天價格沒變（$X）」不畫折線；紀錄在 30 天內才開始的型號不說「30 天」，沒變寫「上架 N 天，價格沒變（$X）」、有變寫「上架 N 天：最低 $X／最高 $Y」照樣畫折線，當天上架寫「今天上架」；沒該型號資料就沒有這行；這件現價跟紀錄的最新一筆 (`historyStats` 的 `last`；同型號多件只記最低那件) 不同時前綴「同型號最低款：」)，選件面板每個品項與 `#chg` 漲跌摘要查得到現價的列各加同一行，唯讀估價單不顯示。空欄顯示新增入口，所有欄位皆可空著。手機更換／移除／數量控制至少 44px 點擊範圍；降低留白不靠截斷品名。
- 「02 打造你的配置」下方有「主機零件｜全部分類」開關 (`site.json` 的 `all_categories: false` 時不顯示)。預設主機零件，畫面與過濾都和純主機站相同；切到全部分類出現「03 其他商品」與新增按鈕，可加原價屋全部 30 類任意多件。關掉開關只藏新增按鈕，已選的其他商品照樣列出並計價。
- 「更換／新增」開原生 dialog，桌面為右側面板、手機為全螢幕；依 slot 或其他商品分類讀型錄。搜尋、群組、排序與價差規則見下節；無結果提供減少關鍵字或清除群組篩選的提示。
- 開啟時焦點進搜尋框；成功選取才套用並關閉，拒絕重複替換時留面板。關閉按鈕或第一次 Escape 不改單，關閉後回到該欄更換／新增按鈕。面板狀態獨立於估價單重繪；數量 1–9 的有效輸入立即計價，失焦時校正無效／空值，重繪保留輸入焦點。
- 沿用 `orig`／`pin`：改選別件用現價，選回原品項還原原 pin；改數量保留 pin，下架品項留原品名與報價。
- 分享單 (`kind === 'shared'`) 改過零件或數量後，`#chg` 下方多一塊 `#diff`「跟分享時的內容 (日期) 比」(2026-10-22 起)：`BuilderUI.diffQuote(orig, cur, find)` 逐格比。標題下小字「這張單改了 N 處；換掉的零件以現價計」並提示按「還原分享時的內容」(`#reset`) 復原；每列「欄位：原品名 (刪除線) → 新品名，原小計 → 新小計 ±$」，同件只改數量寫「數量 a → b」、同件同數量只拿掉鎖價寫「改用現價」，另列「＋ 新增」／「－ 移除」，最後一列是合計差 (沒差寫「不變」)。其他商品欄位寫「其他商品・分類」，用分類＋品名配對、重複品名逐件對。只看 `rowsDirty`：只改店家欄位 (`bizDirty`) 不顯示；唯讀估價單是快照 (`#builder` 整個藏起)，也不顯示。
- 載入／失敗畫面只在資料尚未可用時顯示，失敗有重試入口。即時更新失敗保留已載入的快照；`live_url` 空時維持停用。
- 焦點有清楚外框；價格漲跌與警告同時使用文字／符號，且支援 `prefers-reduced-motion`。
- 唯讀估價單 (`#v=1&q=`)：深色頁面中間一張白色紙本單據 (`.sheet` 內重新宣告同名色彩 token，既有的漲跌／下架樣式自動換成淺色版)。上方動作列：「← 編輯這張估價單」、複製估價單連結、列印／存成 PDF、帶到原價屋估價頁；紙張依序是抬頭 (QUOTATION／估價單／網站名；右上角 `#sheet-qr` 是這張單唯讀連結的 QR Code 加「掃描開啟這張估價單」小字，尺寸隨格數放大 (每格 2 CSS px、最小 104px，≤600px 自己占一列)、列印每格 0.4mm (版本 23 約 47mm)，連結沒變不重畫，店家版也有；連結太長 (超過 2,953 bytes) 時改顯示「連結太長，無法產生 QR Code」提示)、估價名稱／報價日期／現價資料／品項、明細表 (項目／品名／數量／單價／小計)、合計區、備註、免責聲明。檢視模式藏起首頁簡介、報價日期列、說明與手機底部列。
- 編輯模式摘要保留含稅估價總計為主價格，桌機與手機補實付估計（current − off）；有歷史價差時標「依現價估計實付」，避免混為原報價折後價。主按鈕分享唯讀估價單，搭配預覽及次要的可編輯分享；手機固定列保持預覽與分享兩個入口。
- 估價單 ≤600px 螢幕版：名稱全寬、日期／現價資料／件數緊湊排列，明細前補含稅總計。明細一列一張：項目、完整品名、數量・單價・小計（data-label 前綴）；表頭視覺隱藏，tr／td 保留 ARIA role 與表格語意。
- 列印：檢視模式只印紙張，白底黑字、root 改 light color-scheme（否則 PDF 頁邊會是深色）、列與合計不跨頁、跨頁重複表頭。手機頂部總額只在 screen media 顯示，列印保留底部完整合計；編輯模式不印固定列。

## 店家模式

連結格式、驗證與歸屬規則見 [site.md](site.md)「店家模式」。

- 入口：topbar「店家模式」按鈕 (啟用後顯示「店家：店名」)、摘要次要連結「店家模式…」、說明區「給電腦店老闆與業務」段落的按鈕、`#store`。設定是原生 dialog (沿用選件面板版型)：店名必填、業務、電話 (`type=tel`)、LINE ID、地址、標語、啟用開關；儲存、取消、複製店家設定連結、清除這台裝置的店家資料 (confirm)。驗證錯誤顯示在表單內並把焦點移到該欄。
- 店家報價區在左欄 `#warns` 之後 (步驟編號 03／04 依其他商品是否顯示)，不放 sticky 摘要卡 (摘要已約 560px 高，1440×900 要完整可見)。自己的單：原價屋合計、本店價 (`inputmode=numeric`，接受千分位與全形，失焦補千分位)、省多少／比原價屋高的提示、需確認提示與「保留本店價」、服務列與快速新增 (組裝費、灌系統、運費、到府收送、自訂；上限 8 列)、客戶稱呼、有效期限 (date)、備註 (200 字計數)、隱藏原價屋單價 (註明只是畫面不顯示)、本店合計。別家店的單只顯示一段說明，店家模式開著時多一個「改用本店報價」。
- 輸入不跳游標：輸入框只綁一次；`render()` 只更新算出來的數字 (`renderBiz`)，輸入框的值只在換分頁、重設、改用本店報價時回填 (`fillBiz`，以 `filledFor` 判斷，不寫入 `document.activeElement`)。全部分類載入、即時報價的非同步 `select(cur)` 不碰輸入框。打字時網址延遲 400ms 寫入 (`scheduleSync`)，`replaceState` 包 try/catch (Safari 太頻繁會丟 SecurityError)。
- 店家單 (自己的或別家店的) 的摘要與手機固定列大總計改成「本店合計」(需確認時標出)，另列原價屋合計；任搭折／估計實付改標「原價屋…」。自己的單「複製零件清單」變「複製給客戶的訊息」(`BuilderUI.storeMessage`：稱呼、品項型號、原價屋合計／本店價／服務列／本店合計，隱藏模式不列任何原價屋金額，有效期限、需確認提示、估價單連結、業務電話與 LINE)。別家店的單藏「帶到原價屋估價頁」，自己的單保留 (店家進貨用)。分享時本店價需確認或有原價屋已下架品項，toast 多一句提醒。
- 估價單店家版：抬頭右側換成店家區塊 (≤600px 改成全寬信頭放最上方)，電話與 LINE 是連結、手機 44px；meta 加客戶與有效期限 (過期標「已過期，請重新詢價」)，拿掉現價資料；明細欄名改「原價屋單價／原價屋小計」，品名下不寫 ▲▼、下架、條件標籤；隱藏模式改寫 colgroup／thead 只留項目／品名／數量。合計依序：原價屋合計 (隱藏時不列)、本店價 (省多少)、服務列、本店合計 (`.t-final`)。備註最前面是店家備註 (保留換行) 與有效期限，再接相容性提示 (不寫搭板／組裝價等原價屋購買條件)。頁尾聲明換店家版，`#sheet-made` 改「由 <網域> 免費估價工具產生」；藏「帶到原價屋估價頁」，分頁標題用店名。


## 起始配置

- 模板用途順序為文書、入門遊戲、主流遊戲、高階；同用途顯示既有 AMD／Intel 配置，沒有的組合不補造菜單。purpose/platform 的格式與 fallback 見 [site.md](site.md)。
- 泛用配單先讓訪客比較同用途的不同平台；若使用者另指定平台優先的客群或流程，依該要求調整，不把本次選擇泛化成所有網站的規則。
- 無有效配置網址時展開目前用途；有效 #b/#q 收合還原，唯讀連結仍直接開估價單。用途切換只篩選，不改 cur、內容或 hash；點實際配置才切換並收合，焦點回到更換配置按鈕。
- 展開時選中狀態以配置 key 對應，不能依過濾後卡片的 DOM 順序更新。更換配置展開目前用途；收合取消不改單。
- 「最近開過」(2026-10-22 起)：按分享 (主按鈕／手機固定列／估價單動作列的複製估價單連結)，以及檢視模式下 (按預覽或直接開 `v=1` 連結，別人的唯讀分享單也算) 每次 `syncHash`，都由 `rememberRecent` 把 `{n, d, total, hash, at}` 寫進 localStorage `coolpc.recent` (hash 一律是快照連結 `#v=1&q=`，預設配置的預覽也記快照、不記 `#v=1&b=`，跟「複製分享連結」存的是同一筆；空單不記、內容沒變不重寫；店家單的 total 是本店合計；`U.recentUpsert` 新的在前、同 hash 只留一筆、最多 30 筆；讀回先過 `U.recentClean`，壞筆丟掉)。只存連結、不存草稿、不上伺服器。有紀錄時用途列最後多一個「最近開過」(purpose `recent`)：卡片列名稱、報價日期、開過的日期與合計，點了改 `location.hash` 重新載入 (同連結直接 reload)；卡片後面是占滿整列的文字按鈕「清除這台裝置的「最近開過」紀錄」(`.recent-clear`)，confirm 後清掉並回到目前配置的用途 (分享單取其 base 配置)。複製可編輯連結與複製零件清單不記。
- 同一次頁面保留各方案草稿，分享單另有返回入口。預設來源／組裝建議用「配置說明」收合，分享歷史漲跌、下架與條件提示保持可見；不額外加跨重新整理的草稿保存或訪客追蹤；「最近開過」只存估價單連結與摘要 (名稱、報價日期、合計、開過的日期) 在這台裝置的 localStorage，不存編輯中的草稿、不上伺服器。

## 搜尋與換件價差

- 搜尋採 NFKC、大小寫正規化、空白分詞 AND；每個詞都須在品名／群組／分類組合文字中匹配。提示依分類，例如記憶體 32GB 6000、主機板 B850 WIFI；既有下架型號預填保留。
- 規格群組直接取目前型錄；保留其他商品的分類選單。每次開面板重設群組與排序，不沿用前一次隱藏條件。
- 原價屋順序保留群組標題；現價單價升／降序跨群組排列，每件補群組標籤，同價維持原順序。跨分類先完整篩選排序，再取最多 300 件，同時顯示總符合數與顯示數。
- 價差預覽共用實際 selectCandidate 規則但不改資料；基準是套用後 quoted − 目前 quoted，包含數量、歷史 pin、選回原件與其他商品合併。不扣任搭折，面板標「依目前數量計算，任搭折扣另計」。
- 替換已有的其他商品時維持拒絕與提示，不顯示數字價差；新增同件則合併數量，上限 9 時預覽增加為 0。避免只用型錄單價相減，或複製一套不同的預覽計算。

## 驗收

1. 在暫存目錄跑 `--init`，確認 HTML、CSS、coolpc-live.js、builder-ui.js 都存在且相對路徑能載入；再跑一次確認既有客製檔案保留。用生成的專案執行副本產出 `data.json` 與 `history.json` (再跑一次 `history.json` 要逐位元相同)，避免漏掉腳本或模板相依。
2. 執行 `node --test '<技能目錄>/tests/*.test.js'` (Node 22 的 `--test` 不接受目錄參數，CI 用這個 glob；本機 Node 26 給目錄也能跑) 與 `python3 -m unittest discover -s <技能目錄>/tests`；JS 解析一致性測試需要專案內原始 `evaluate.php` 與解析快照，不具備時會略過該項。
3. 在 1440、1209、1024、768、390px 檢查載入、長品名、無橫向溢出、摘要／固定列、dialog 與說明區。以瀏覽器驗收型錄最大分類。此 repo 的無 hash 首頁：1209×954 首屏見首件與摘要價格，390×844 見首件開始處及固定列；各寬度無水平溢出。
4. 實測用途篩選不改單／hash、選定收合、方案／分享單草稿往返、缺 metadata 的配置、多詞／全形／無結果、群組及穩定排序、選取／取消、移除／新增、數量 1/2/9、重設、焦點與空單。價差需等於套用後總計差，含鎖價、下架、優惠結束與重複合併。
   - 部分瀏覽器工具的 fill 不等於原生 change；確認總計及 hash，不能只看 input.value。鍵盤輸入有效數量、離開欄位與第一次 Escape 關閉都要實測。
   - 測新版本或無 hash 首頁時先導航到目標，再明確 reload；同 URL／片段導航可能保留舊文件、面板或記憶體狀態。
   - 全部分類：預設不載 `data-more.json`；切開關才載、重新整理後記得開關；分類下拉列整類 (螢幕約 700 多件)、跨分類先排序再取 300，顯示完整符合數；同一件加兩次變數量 2；含其他商品的分享單重開會先載完整型錄，開關關著時其他商品仍列出、新增按鈕隱藏。
   - 把 `data.json` 的 `more.url` 暫時指向不存在的檔模擬載入失敗：其他商品以報價計並標「其他分類的報價載入失敗」，切開關重試成功後改回現價。測完還原。

5. 用歷史分享單驗證舊價、▲▼、下架、改用現價、還原／選回原品項、複製清單與分享連結重開。用暫存資料或測試伺服器模擬載入失敗與重試，不改正式快照。
   - 唯讀估價單：`#v=1&q=RAW` 進檢視且網址原樣不重編；`#v=1&b=mid` 進檢視無 toast；截斷的 `#v=1&q=` 回編輯並 toast「分享連結無法讀取」；`#v=1`、`#v=1&b=不存在` 開預設配置的編輯模式；`#b=mid&cpu=4:22` 仍有舊版 toast。編輯 ↔ 預覽來回改過的內容保留，回編輯回到原捲動位置與按鈕；空單預覽只 toast。

   - 分享：`copyText` 收到 promise (連結還在壓縮) 且瀏覽器有 `ClipboardItem` 時走 `navigator.clipboard.write`，否則 `writeText`，兩個都要 stub (write 收到的 `ClipboardItem` 用 `getType('text/plain')` 拿 Blob 再 `.text()` 讀出文字)。`syncHash` 只對改過的單先算 `encoded`，所以沒動過的預設配置在編輯模式第一次按分享會走 write，再按一次或改過單後才有快取 (`shareUrlNow`) 走 `writeText`；檢視模式畫 QR 時已先算好。確認主按鈕／手機／估價單複製都是 `#v=1&q=2…`、可編輯連結是 `#q=2…` (沒動過的分享單沿用原字串，舊的 `1…` 照舊)、複製清單最後一行是估價單連結。
   - 內容：拿 build 品項做連結、RAM 價格減 500 → 該列「現價 $X ▲500」、合計區「以現價計 ▲500」；不存在的品名 → 「已下架」與「N 項查無現價，以報價計」；任搭折品項 → 任搭折扣與估計實付；品名或 `n` 放 `<img onerror>` 只顯示成文字 (含分頁標題)。
   - 壓縮連結 (2026-10-22 起)：新產生的分享連結是 `#v=1&q=2…`／`#q=2…`，舊的 `1` 字首連結照樣開得起來且網址原樣不重編；重新整理後先把 `CompressionStream` 設成 undefined 再改件、分享要退回 `1` 字首 (壓縮結果有快取，順序反過來會拿到先前算好的 `2`)；`2` 字首截斷 → toast「分享連結無法讀取（連結不完整…）」回編輯模式並退回預設配置；解開超過 256KB → 「連結內容過大」、沒有 `DecompressionStream` 的瀏覽器開 `2` → 「這個瀏覽器太舊…」(這兩項 Node 測試已涵蓋)。8 列主機單約 1,243 → 1,028 字元，中文品名難壓、省幅有限，其他商品多時才明顯。
   - 店家模式：關閉時上述檢查全部照舊。設定 → 驗證 (店名含原價屋、壞 LINE ID) → 填本店價／服務列／客戶／期限／備註，網址與重新整理都保留；改零件或數量出現需確認、改回或「保留本店價」解除；重設還原本店價；分頁切換各自保留。預覽店家版 (抬頭、撥號 / LINE 連結、隱藏模式無任何原價屋金額)、清掉本機店家資料後以客人身分開同一連結 (唯讀說明、無帶單按鈕、改零件後「請向店家確認」)、別家店連結 (唯讀、改用本店報價、重設還原)、`#s=` 設定連結 (確認畫面、差異標示、取消不改資料、無舊版 toast)。所有店家欄位放 `<img onerror>`／`<svg onload>` 只顯示成文字 (含分頁標題)。用 HEAD 版 docs 開店家連結確認舊頁不報錯。
